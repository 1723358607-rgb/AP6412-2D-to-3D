# 游戏设定 v1.0

## 1. 定位与参考

暂名《彩块工坊》。参考 Royal Match 的基础三消、限步目标与相邻消除破坏木箱机制；关卡是本项目的定制配置，不宣称复刻或核实 Royal Match 同一版本的前三关。

参考资料：
- 基础玩法：https://dreamgames.helpshift.com/hc/en/3-royal-match/faq/4-how-can-i-play-the-levels/
- 木箱：https://dreamgames.helpshift.com/hc/en/3-royal-match/faq/351-box/
- 特殊棋子参考：https://dreamgames.helpshift.com/hc/en/3-royal-match/faq/6-creating-and-using-the-power-ups/

本项目初版不做特殊棋子：四连、五连或交叉匹配按普通消除处理，不生成火箭、炸弹等。使用自己的简单图形、模型与界面素材。

## 2. 范围

- 7×7 棋盘，四种普通棋子，颜色和形状同时区分。
- 点击一枚棋子，再点击上下左右相邻棋子进行交换；不要求拖拽。
- 木箱是固定占格障碍，分一层和两层，不能移动、交换或参与匹配。
- 交换 → 匹配 → 消除/木箱伤害 → 下落/补充 → 连锁 → 判定结果。
- 无计时限制。初版无付费、体力、装修、联网、特殊道具或道具组合。
- 2D 和 3D 使用相同关卡配置、种子、规则及星级算法。

## 4. 规则边界

1. 仅普通棋子可交换；空位、木箱、越界、非相邻格一律拒绝，不扣步。
2. 交换必须在交换位置形成横向或纵向连续至少三枚同色；无效交换回退，不扣步。
3. 有效交换只扣 1 步，之后的全部连锁不另扣步。
4. 同一轮结算同时找出全部匹配格，用集合去重后消除；交叉格不会重复计数。
5. 某木箱只要与本轮被消除的普通棋子上下左右相邻，就减一层。同轮最多减一层；下一轮连锁可再次减层。
6. 木箱不下落。每列按仍存在的木箱分成连续可用区段；各区段内向下压实，并从区段上端补齐。允许在内部区段入口生成棋子，这是本项目的明确简化。木箱被清除后，按新连通区段结算。
7. 下落和补充后再次检查匹配，直到棋盘稳定。显示动画只是逻辑结果的表现，不决定规则结果。
8. 棋盘结算及动画期间锁定棋盘输入；返回/重试须先安全取消旧会话，不让旧回调影响新关卡。
9. 开局无自动匹配，且至少存在一个有效交换。
10. 稳定棋盘无有效交换时，重排普通棋子，保留木箱位置/层数和步数；重排后无现成匹配且有有效交换。使用有上限的确定性尝试和明确失败处理，禁止无限循环。
11. 一次操作的全部连锁结束后，先检查目标完成，再检查步数耗尽；最后一步完成目标仍获胜。
12. 已胜利或失败后拒绝棋盘操作，不重复发出结算。重试复位棋盘、步数、目标和随机序列。

## 5. 星级和进度

仅通关可获得星级。使用整数计算避免浮点边界：

- 三星：`moves_remaining * 5 >= initial_moves * 2`。
- 二星：未达三星且 `moves_remaining * 5 >= initial_moves`。
- 一星：通关但未达二星。
- 失败：零星。

| 关卡 | 一星剩余步数 | 二星剩余步数 | 三星剩余步数 |
|---|---|---|---|
| 1，15 步 | 0—2 | 3—5 | ≥6 |
| 2，20 步 | 0—3 | 4—7 | ≥8 |
| 3，24 步 | 0—4 | 5—9 | ≥10 |

- 每关保存历史最高星数：`best = max(old_best, earned_stars)`；失败不覆盖成绩。
- 第一关始终解锁；上一关历史星数大于零时解锁下一关，不要求三星。
- 重玩不会重新锁关；重复接收相同结果不降低成绩。
- 2D 和 3D 使用独立存档文件，避免演示时互相污染。实际进度应跨应用重启保留。

## 6. 页面与流程

| 页面 | 必需内容 |
|---|---|
| 开始 | 标题、开始游戏 |
| 选关 | 三张关卡卡片、各关历史最高三颗星、锁定状态、返回开始 |
| 游戏 HUD | 关卡名、剩余步数、剩余木箱、返回选关；棋盘由玩法侧提供 |
| 胜利 | 本次星级、剩余步数、重试、返回选关；非最后关可下一关 |
| 失败 | 失败提示、重试、返回选关；本次零星 |
| 第三关胜利 | 全部关卡完成提示、重试、返回选关 |

未结束时离开关卡需确认；取消后继续当前局，确认后停止当前会话并返回。第一版不保存未结束棋盘。

UI 显示本次星数与历史最佳时须区分含义；本次一星、历史三星时，不把结算误显示为本次三星。

## 7. 2D/3D 边界

核心棋盘以行列数据表达，不包含屏幕像素、三维坐标、相机或节点路径。2D/3D 的表现层把点击映射为同一行列坐标，并消费同一操作结果。

3D 使用真正三维棋子与木箱、相机及选取映射；可以保留平面棋盘结构和正交相机。禁止让物理自由落体决定补充和匹配。UI 层保持普通屏幕 UI，可复用。
